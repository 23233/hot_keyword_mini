## 一、目标与边界

### 1.1 目标

本轮开发交付一个可复用的 SDUI 通用能力平台：

- 小程序前端只保留通用运行时，不为某个小程序编写业务页面组件；
- 页面通过统一 SDUI 信封请求、校验、解析、渲染和执行动作；
- 页面、路径、导航、内容、业务分支和能力开关由后台配置并发布；
- 两个 AppID 使用相同的 Block、Action、协议版本、缓存、降级、审计和 MCP 编排链路；
- 支付、上传、地图、客服、聊天、订单、物流、售后、斗师接单、WebView、会员、广告、提现等能力在本轮完成通用抽象和运行时内置；
- 具体业务是否开启由租户能力矩阵、后端真实契约、审核状态和页面发布门禁共同决定。

### 1.2 不允许的实现方式

- 不为“设身处地游戏”或“斗艺馆”单独复制一套页面渲染器；
- 不把支付、订单、聊天、上传等能力写死在某个页面组件中；
- 不把 `custom`/`custom_block` 当作支付、资金、订单、上传或聊天的业务实现；
- 不通过任意 URL、任意 HTTP 请求、脚本、SQL、Cookie 或 Authorization 注入扩展协议；
- 不把前端显示/隐藏当作权限控制，公开接口必须同步执行租户、页面、能力和领域权限校验；
- 不把“Block 能显示”当作“业务能力已完成”。

### 1.3 两个 AppID 的关系

| --- | --- | --- | --- |
| 设身处地游戏 | `wx7a779add6a689881` | 独立微信 AppID、独立审核和域名配置 | 游戏首页、游戏中心、游戏详情、游戏兑换码、复制、导航、已登记 WebView |
| dcl/斗艺馆 | `wx8b8e899d4829481a` | 独立微信 AppID、独立审核和域名配置 | 本地先验收通用运行时和首发页面族；能力按后台矩阵启用 |

两个 AppID 共享代码和协议，不共享微信审核结果、隐私协议、支付配置、域名白名单或业务数据。当前阶段只使用本地开发环境，禁止把本地测试密钥、腾讯地图密钥、微信支付私钥或客服配置写入仓库。

### 1.4 本地开发约束

- 本地数据库中预置两个租户：`wx7a779add6a689881`、`wx8b8e899d4829481a`；
- 所有页面、能力矩阵、WebView 域名、资源和审计记录必须带 `app_id`；
- 本地环境允许使用 fixture、Mock 领域端点和微信开发者工具调试，但协议、权限、状态机和错误码必须与真实后端保持一致；
- 不连接生产数据库、生产 COS、生产支付回调或生产客服队列；
- 后续切换测试/生产环境只允许通过配置，不修改 Block 和页面协议；
- 两个 AppID 必须使用同一套验收脚本分别运行，不能用一个 AppID 的结果代替另一个。

## 二、统一运行时模型

客户端固定执行以下流程：

```text
请求页面
  -> 校验协议版本和能力声明
  -> 解析受控数据绑定
  -> 渲染 Block
  -> 执行白名单 Action
  -> 保存局部状态/请求结果
  -> 展示成功、加载、空态、错误或降级状态
```

### 2.1 协议组成

统一信封至少包含：

- `protocol_version`、`schema_version`、`request_id`；
- `page`：页面 ID、revision、标题、主题、Block 树和分享配置；
- `data`：按数据源声明装配的非敏感业务数据；
- `capabilities_required`：页面实际依赖的能力；
- `cache`：ETag 和缓存时间；
- `fallback`：安全首页或维护页；
- `viewer`：登录、会员和权限摘要，不下发凭证。

### 2.2 Block 规范

每个 Block 必须具备：

- 稳定 `type` 和版本；
- 明确的 `props` Schema；
- `loading`、`empty`、`error`、`fallback` 状态；
- 可选的 `visible_when`、`repeat` 和数据绑定；
- 可选 `action`/`events`，动作只能引用白名单 Action；
- 苹果 HIG 风格的稳定尺寸、间距、字号、颜色和可访问性语义；
- Web/H5 预览、微信开发者工具和真实小程序运行时的一致表现。

### 2.3 Action 规范

Action 必须具备：

- 稳定动作类型和参数 Schema；
- 是否需要登录、能力依赖、确认弹窗和幂等键规则；
- 成功、失败、取消、超时和重试行为；
- 受控端点、字段白名单和错误码；
- 不允许把动作实现放到业务页面组件中。

## 三、通用能力包清单

每个能力包必须同时交付四层：

1. **SDUI 表达层**：Block、状态、事件和协议 Schema；
2. **客户端适配层**：Action、微信原生 API、缓存、轮询/WebSocket、上传进度和降级；
3. **后端领域层**：模型、权限、事务、幂等、状态机、回调、审计和错误码；
4. **运营控制层**：租户开关、页面显示/隐藏、版本、域名、审核状态和发布门禁。

| 能力包 | 通用 Block | 通用 Action/平台适配 | 后端最低契约 |
| --- | --- | --- | --- |
| 页面与导航 | `container`、`stack`、`grid`、`tabs`、`list`、`bottom_nav`、`floating_action` | `navigate_page`、`set_state`、`refresh` | 页面路径、目标参数、显示/隐藏、首页目标、回退页 |
| 游戏资料与兑换码 | `game_header`、`game_card`、`redeem_code_card` | `request_data`、`copy_text` | 游戏资料、库存、匿名/会话领取、幂等、限流、敏感字段保护 |
| 支付 | `product_card`、`order_summary`、`price_breakdown`、`payment_result` | `create_order`、`pay`、`refresh_order`、`request_payment` | 价格快照、订单、支付参数、回调验签、退款和幂等 |
| 用户上传 | `media_picker`、`upload_progress`、`media_gallery` | `choose_media`、`upload_file`、`delete_media` | 预签名 URL、文件限制、内容安全、归属、删除权限 |

## 四、通用后端与后台配置

### 4.1 租户级能力矩阵

每个 AppID 必须有能力矩阵，至少记录：

```json
{
  "capability": "payment",
  "state": "disabled",
  "protocol_version": "1.0",
  "minimum_client_version": "1.0.0",
  "review_status": "not_submitted",
  "domain_keys": [],
  "updated_by": "admin"
}
```

能力状态固定为：

- `disabled`：协议存在但业务关闭；
- `configured`：后端配置完整，尚未对外开启；
- `enabled`：允许页面使用；
- `blocked`：被审核、权限、域名、资质或安全门禁阻断；
- `degraded`：服务异常，页面必须展示降级状态。

### 4.2 页面发布门禁

页面发布前后端必须检查：

- 所有 Block 已在公共注册表中；
- 所有 Action 已在公共注册表中；
- 页面依赖的能力在该 AppID 中不是 `disabled` 或 `blocked`；
- 数据源属于当前租户且字段在白名单内；
- WebView 只能引用已登记 `url_key`；
- 页面路径未隐藏，目标页面已发布；
- 页面使用的最低客户端版本不高于当前审核版本；
- 隐私、类目、域名和支付/资金配置门禁通过；
- 页面有可用的错误态、空态和安全回退页。

不满足任一条件，发布接口、后台发布按钮和 MCP `sdui.page.publish` 必须返回机器可读错误，不得写入线上页面。

### 4.3 页面与能力的动态控制

后台必须支持：

- 页面草稿、预览、校验、发布、回滚；
- 页面显示/隐藏和路径禁用；
- 首页目标切换；
- 导航入口排序、显示/隐藏和目标参数；
- Block 属性、数据源和 Action 配置；
- 能力包启用/禁用及状态原因；
- WebView `url_key`、用途、域名、版本和下线；
- 每次发布的 revision、操作人、能力快照和验证记录。

## 五、MCP 配置与编排验收

MCP 必须复用后台同一套服务，不得另写一套页面逻辑。工具至少覆盖：

- `sdui.app.list`：读取租户、AppID 和能力状态；
- `sdui.capability.list`：读取公共能力包、Block、Action、版本和状态；
- `sdui.capability.validate`：校验指定页面使用的能力；
- `sdui.acceptance.run`：只读生成指定 AppID 的验收清单，汇总协议校验、能力矩阵、Layout IR、Block/Action 覆盖以及 Web/微信证据要求；不发布页面、不启用能力、不调用生产服务；
- `sdui.page.list/get`：读取页面、草稿、隐藏状态和 revision；
- `sdui.page.create/patch/validate/preview`：创建和修改草稿；
- `sdui.page.screenshot`：生成页面截图和哈希；
- `sdui.page.publish/rollback/set_current`：受权限和人工确认门禁保护；
- `sdui.file.prepare_upload`：申请受控预签名上传；
- `sdui.webview.list/validate`：管理和校验 `url_key`；

MCP 验收规则：

- `sdui.acceptance.run` 只负责生成验收任务和当前静态检查结果，不能替代 `page.validate`、`page.preview`、`page.screenshot` 或微信开发者工具的实际执行；

- AI 必须先读取 `sdui://rules`、`sdui://api` 和能力清单；
- 所有写入操作必须显式传入 `app_id`、`page_id` 和 `expected_revision`；
- 默认只写草稿；发布、回滚、切换首页必须具备 `release` 权限并传入 `confirmed: true`；
- MCP 与后台必须调用同一个发布校验器，不能出现后台能发布、MCP 绕过门禁的情况；
- 工具失败必须返回 `code`、`tool`、`message`、`recovery` 和涉及的能力/Block/Action；
- 不允许通过 MCP 获取 AppSecret、支付私钥、任意数据库数据或执行任意 HTTP/脚本。

## 六、行业通用业务规则基线

以下规则用于本地开发和协议验收，不代表最终经营政策。规则必须做成后端状态机、权限策略和后台参数，Block 只展示状态和触发动作。

### 6.1 斗师认证与接单

- 斗师状态：`draft`、`submitted`、`under_review`、`approved`、`rejected`、`suspended`、`closed`；
- 实名、联系方式、服务范围、资质材料和收款信息分开审核，敏感材料只返回脱敏状态；
- 只有 `approved` 且未 `suspended` 的斗师可以开启接单；
- 接单开关、服务类型、服务区域、可用时间和最大并发订单必须后台配置；
- 任务状态：`pending`、`offered`、`accepted`、`quoted`、`paid`、`in_service`、`awaiting_confirmation`、`completed`、`cancelled`、`disputed`；
- 报价必须包含服务项、价格、有效期、预计周期和取消规则；用户确认并完成支付后才进入服务执行；
- 斗师拒绝、超时未接单、排期冲突和平台暂停都必须产生可审计事件。

### 6.2 结算、提现与资金

- 所有金额使用分为单位，订单、退款、平台服务费和斗师应结算金额保存不可变快照；
- 结算状态：`pending`、`available`、`frozen`、`processing`、`paid`、`failed`；
- 订单完成、售后期结束或平台确认后才进入可结算余额；
- 提现需要绑定收款账户、风控校验和人工/规则审核，重复请求使用幂等键；
- 余额账本只追加，不直接覆盖历史金额；退款、扣款和平台调整必须记录原因和操作人；
- 本地环境使用虚拟账本和支付沙箱，不调用真实提现或真实资金接口。

### 6.3 订单、物流与售后

- 订单状态转换必须由服务端状态机验证，客户端不能直接写入目标状态；
- 实物服务支持收件、服务中、待确认、回寄、完成等阶段，并记录时间线和证据；
- 售后类型至少包括取消、退款、服务争议、物流异常和质量申诉；
- 售后状态：`requested`、`evidence_required`、`under_review`、`approved`、`rejected`、`refunded`、`closed`；
- 证据上传必须经过内容安全检查并与订单/售后单绑定；
- 平台裁决和退款属于不可逆动作，必须二次确认、权限校验和审计记录。

### 6.4 会员、广告与内容商业化

- 会员状态：`inactive`、`active`、`expired`、`paused`、`cancelled`；
- 会员权益必须按租户、套餐、有效期和权益键配置，页面只展示服务端计算结果；
- 广告位必须使用受控 `ad_slot`，包含广告位 ID、展示策略、频控、落地页白名单和关闭开关；
- 广告不得覆盖支付、客服、上传、定位或不可逆操作按钮；
- 会员购买、续期、退款和权益发放必须绑定订单并保证幂等；
- 本地环境使用测试套餐、测试广告和虚拟权益，不接真实广告投放或真实扣款。

### 6.5 两种客服模式

- 默认模式：微信内置客服组件，Action 为 `open_wechat_service`，由微信负责会话承载；
- 可选模式：小程序内客服，使用 `chat_thread`/`message_list` 等通用能力，由平台负责会话、未读、消息审计和离线恢复；
- 页面通过租户能力矩阵选择客服模式，不能在页面代码中写死；
- 内置客服不可用时，可以回退到已登记二维码或小程序内客服，回退策略由后台配置；
- 客服来源、页面、游戏/商品/订单 ID 必须作为受控上下文参数传递，不传递敏感 Token。

### 6.6 腾讯地图与定位

- 地图服务统一抽象为 `map_provider=tencent`，页面只使用通用坐标、地址和范围协议；
- 腾讯地图 Key、签名和服务端密钥只能通过本地/环境配置注入；
- 客户端负责授权、选点和地图展示，服务端负责地址标准化、坐标转换、服务范围和配送范围判断；
- 用户拒绝授权、定位失败、地图 SDK 不可用时必须展示可操作的手动地址输入/选择状态；
- 不把精确位置写入页面公开协议或日志，除非获得明确业务授权。

## 七、视觉验证要求

### 7.1 每个 Block 的最低验证状态

每个公共 Block 必须至少验证：

1. 正常态；
2. 加载态；
3. 空态；
4. 错误态；
5. 禁用态或权限不足态；
6. 长文本、长列表、缺图、异常数据和窄屏；
7. 触发动作后的成功、失败、取消和重复点击；
8. 与相邻 Block 的间距、层级、圆角、阴影、颜色和文字换行。

### 7.2 视觉证据

每个 Block 和每个能力包必须保留：

- 页面协议 fixture；
- 后端 `layout_ir`；
- 微信开发者工具截图；
- Web/H5 预览截图；
- iPhone 12/13 Pro 和至少一个窄屏截图；
- 视觉哈希、协议 revision、客户端版本和能力矩阵快照；
- 已知差异说明和复测结果。

验收重点：不得白屏、重叠、溢出、文字遮挡、底部安全区被覆盖、按钮跳动、图片变形、状态切换后布局错位或动作执行后页面状态不一致。

### 7.3 微信开发者工具/MCP 验证

每个能力包至少完成一次真实微信小程序运行时验证：

- 用对应 AppID 构建并打开开发者工具项目；
- 请求真实 SDUI 页面信封，验证协议版本、Block 和能力声明；
- 对页面中的每个 Action 执行一次主流程和一次失败/降级流程；
- 校验微信原生适配：支付调起、媒体选择/上传、定位、地图、客服、WebView、剪贴板、订阅消息和消息轮询等；
- 检查控制台无未解释错误、请求无跨租户数据、未知能力不会执行；
- 截图回传到验收记录，和 `layout_ir`/视觉基线进行对照；
- 两个 AppID 均需通过同一套验收脚本，不能只验证一个 AppID 后推定另一个可用。

开发者工具 CLI、MCP 或其他自动化入口只能调用公共运行时和公共后端接口；不能通过测试专用分支绕过真实协议。

## 八、两个小程序验收范围

### 8.1 设身处地游戏

首发页面只启用：

- 动态首页；
- 游戏中心；
- 游戏详情；
- 游戏兑换码；
- 游戏介绍、封面、图标、版本和标签；
- 兑换码受控请求、复制和错误态；
- SDUI 底部导航/浮动入口；
- 已登记 HTTPS WebView。

不启用旧用户中心、AES、JWT、自动兑换、兑换记录、防屏蔽工具、UGC、关注和原生 TabBar。兑换码请求允许匿名，服务端仅保留库存和幂等所需的最小技术记录，不提供用户可见领取历史。

但公共运行时必须完成能力包注册；支付、上传、地图、客服、聊天、订单、物流、售后、斗师接单、会员、广告和提现在该租户初始为 `disabled`。

### 8.2 dcl/斗艺馆

运行时必须复用第一小程序的协议和渲染器。页面能力按领域启用：

- 内容、百科、品牌、斗师、作品和商品展示；
- 搜索、筛选、画廊、表单、客服承接；
- 会员、支付、上传、地图、聊天、订单、物流、售后、斗师接单、广告和提现；
- 页面路径、导航和功能分支的服务端显示/隐藏；
- H5/WebView 入口和安全回退。

`dcl` 当前 H5 Mock 只能作为视觉参考和 fixture 来源，不能作为真实业务验收依据。每个已启用能力必须有真实后端端点、权限、状态机和错误态。

## 九、验收门禁与交付物

### 9.1 公共平台门禁

- Go 项目通过 `go test ./...`；
- Go 项目通过 `go build ./...`；
- 小程序通过类型检查、协议测试和微信构建；
- 所有公共 Block 都有协议、渲染器、状态 fixture 和视觉证据；
- 所有公共 Action 都有白名单、参数校验、错误态和客户端适配测试；
- 两个 AppID 都完成租户隔离、能力矩阵和发布门禁测试；
- 后台和 MCP 对同一页面得到相同校验结果；
- 隐藏页面不能通过公开路径、首页或导航访问；公开路径请求必须安全兜底到已发布且未隐藏的首页或维护页，响应不得包含被隐藏页面的标题、Block 或业务数据；
- 任意未知 Block、Action、URL、能力或跨租户参数都被拒绝；
- 发布、回滚、首页切换、能力启用和 WebView 变更都有审计记录。

### 9.2 每个能力包门禁

能力包必须同时提供：

- 协议 Schema 和示例 fixture；
- Block 注册和渲染；
- Action 注册和原生适配；
- 后端端点、数据模型、状态机、错误码和幂等规则；
- 后台配置和能力状态；
- MCP 读取、校验、预览和验收入口；
- 正常/加载/空/错误/禁用/权限/重复操作验证；
- Web 预览截图、微信开发者工具截图和验收哈希。

### 9.3 交付顺序

1. 冻结公共协议、能力注册表、状态模型和错误码；
2. 完成通用运行时和公共 Block/Action；
3. 完成后台能力矩阵、发布门禁和 MCP 工具；
4. 完成每个 Block 的视觉 fixture 和微信开发者工具验证；
5. 接入设身处地游戏四页并通过第一个 AppID 验收；
6. 接入 dcl 首发页面族并通过第二个 AppID 验收；
7. 再按领域真实状态启用支付、订单、聊天、售后、斗师接单和资金能力；
8. 每次能力启用都复用同一套协议和验收脚本，不新增小程序专用实现。
